# Supervised encoder fine-tuning

This experiment addresses the distinction between the repository's frozen-feature
benchmark and supervised fine-tuning. It attaches a classification head to AVES
or BioLingual and jointly optimizes the complete **audio encoder** and the head on
OpenWhistle Classification.

For BioLingual, the CLAP text tower is intentionally frozen because it is not used
by audio classification. The complete audio tower and its projection remain
trainable.

## Protocol

- Dataset: `dolphinteam/OpenWhistle-Classification-Finetuning`.
- Default configuration: `balanced`.
- Model selection: best validation macro-F1 with early stopping.
- Final evaluation: the test split is used once, after reloading the selected
  validation checkpoint.
- Primary metric: test macro-F1.
- Repetitions: three seeds (42, 43, and 44).

This is end-to-end supervised fine-tuning. It must be reported separately from
the frozen embeddings plus logistic-regression results in `experiments/benchmark`.

## Installation

Use the benchmark environment:

```bash
python -m pip install -r experiments/benchmark/requirements.txt
```

## Run both encoders

From the repository root:

```bash
bash experiments/finetuning/run_classification.sh
```

The default AVES run initializes the original `aves-base-bio` checkpoint through
`esp-aves`. The default BioLingual run initializes
`davidrrobinson/biolingual` through Transformers.

Each seed writes:

- `best.pt`: checkpoint selected exclusively on validation macro-F1;
- `results.json`: validation score, test macro-F1, accuracy, confusion matrix,
  parameter counts, and training history.

## Run one experiment

```bash
python experiments/finetuning/src/finetune_classification.py \
  --backbone aves_bio \
  --dataset_config balanced \
  --output_dir experiments/finetuning/results/aves_bio/seed_42 \
  --seed 42
```

BioLingual typically requires more memory, so the supplied runner uses a smaller
physical batch and gradient accumulation. Reduce `--batch_size` further if
necessary while increasing `--gradient_accumulation_steps` to preserve the
effective batch size.

## Full rebuttal sweep

From the repository root:

```bash
bash experiments/finetuning/run_hf_collection_all_tasks.sh
```

This evaluates the shared Hub checkpoint registry on balanced, unbalanced, and
all classification configurations, then on seven-label detection. Classification
selects the validation macro-F1 checkpoint; detection selects validation mAP.
Each experiment evaluates the selected checkpoint on test, using seeds 42–44.
BTB3 checkpoints use the same three-band transform as the frozen-feature
benchmark. For AVES-core and the baseline encoders, see
`run_aves_core_finetuning.sh` and `run_core_models_classification_v2.sh`.

To inspect the commands without downloading models or training:

```bash
python experiments/finetuning/src/run_hf_collection_finetuning.py --dry_run
python experiments/finetuning/src/run_hf_collection_detection.py --dry_run
```

The checked-in `results/` contains existing JSON/CSV reports. Checkpoints,
training logs, and embedding caches remain local. Reports from earlier runs are
preserved with their original model IDs and training history; they are not
regenerated by integrating the code.
